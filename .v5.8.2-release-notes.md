# v5.8.2 — Plan tab task switch saves outgoing timer

## Bug fix

Starting a different pinned to-do from the **Plan** tab (or the menu-bar
popover) while a timer was already running discarded the outgoing session
instead of saving it. The floating pill switcher worked correctly because
it called `stopTimer()` before `startTimer()`.

## Fix

`startTimer()` in the main process now calls `stopTimer()` when a timer
is already running or paused, before starting the new task. This covers
every surface that calls `startTimer` (Plan tab, popover, dashboard)
without duplicating stop-then-start logic in each renderer.

When timesheet confirmation is enabled, the confirm popup for the
outgoing session is preserved (not cleared by the new `startTimer` call).
