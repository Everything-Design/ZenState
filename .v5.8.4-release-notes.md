# ZenState v5.8.4 — Weekly allocation and safer updates

## Your weekly allocation in ZenState

Open **Weekly allocation** in the left menu to see your saved project allocations from Everything Ops alongside time recorded in Basecamp. Compare planned, recorded and remaining hours for the same person, project and week, or browse earlier weeks.

- Allocated billable projects appear first. Other billable projects with recorded time appear in a separate dropdown, including inactive projects and projects outside your current membership.
- Non-billable projects stay out of this planning view.
- Recorded hours are green below the plan, yellow when they match, and red when they exceed it. Overruns remain visible as “hours over”.
- “No allocation” is distinct from an explicit zero-hour allocation.
- A compact sync-status card shows how current the imported Basecamp time is. Running or unposted time is not counted as posted Basecamp time; new entries appear after Everything Ops imports them.

Weekly allocation is optional and read-only. It does not block recording when hours run out, and an Everything Ops outage does not interrupt your timer or Basecamp posting.

## Safer quitting and updating

- Quit and Restart for update now wait while a timer is running or paused, a time confirmation is pending, or a Basecamp submission is in progress.
- Mac update restarts wait until the native updater has prepared and verified the download.
- Failed update checks show a clear message instead of reporting “up to date” or displaying a long technical error.
- Older local-only and unposted sessions are retained rather than being removed by history cleanup.
- Updated Electron and dependencies with compatible security fixes.

## Windows, Mac and Linux

This release includes Windows x64, Apple Silicon Mac, Intel Mac, and Linux x64 packages for Ubuntu, Linux Mint and Debian. Linux users can choose a Debian installer or an AppImage.

Windows builds are unsigned. Mac builds retain the existing signing identity and are not notarized. These are internal office builds; installation prompts depend on the computer’s security settings.

## Update information

The complete release must contain `latest.yml`, `latest-mac.yml`, and `latest-linux.yml` alongside the matching installers, Mac update ZIPs and blockmaps. Publishing these together addresses the missing Windows `latest.yml` error in v5.8.3.

Existing installations check the stable update channel. Linux installations receiving ZenState for the first time need a manual install. An installation whose existing updater cannot complete an upgrade may require the matching installer; install over the existing app without deleting its data.
